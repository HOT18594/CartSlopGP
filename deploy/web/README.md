# Cart Slop GP — Cloudflare hosting package (`web_deploy/`)

Deployable static-hosting package for the **Godot Web client**. It takes the
stamped Web export from `pi_setup/build_0_8_7.ps1` and turns it into a
versioned, immutable-cacheable release on Cloudflare, with a hard
version-parity guard so the `/play` incident (a 0.7.1 build served while the
game was 0.8.6) cannot happen again.

The Pi keeps the real-time parts: the relay, lobby/race HTTP API and the
console. The CDN only serves static bytes. **Nothing in this package deploys
itself** — every upload is a manual, owner-approved command with an API token
that is never written to disk.

```
                 owner workstation                          Cloudflare edge
  ┌───────────────────────────────┐            ┌────────────────────────────────┐
  │ godot_project (0.8.7)         │            │  play.<domain>                 │
  │   └─ build_0_8_7.ps1          │            │   /               302 -> entry │
  │        └─ Web export ─────────┼── stage ──▶│   /version.json   no-store     │
  │             + version.json    │  (guard)   │   /game/0.8.7/<build>/…         │
  │                               │            │       index.html  no-store     │
  │ web_deploy/scripts/…          │            │       index.wasm  immutable    │
  │   stage → precompress →       │            │       index.pck   immutable    │
  │   upload (R2+Worker / Pages)  │            │   (brotli/gzip negotiated)     │
  └───────────────────────────────┘            └────────────────────────────────┘
              │                                                   ▲
              │ CARTSLOP_WEB_BASE on the Pi /play launcher ───────┘
              ▼
  Pi 192.168.1.22  relay + /api + /play fallback (/game/ copy)
```

## Why R2 + Worker, not Pages, for the game client

Cloudflare Pages has a documented **25 MiB maximum file size per asset**
(<https://developers.cloudflare.com/pages/platform/limits/>). The 0.8.7 Godot
Web export is:

| file | raw | > 25 MiB? |
| --- | ---: | --- |
| `index.pck` | 120.9 MB | **yes** |
| `index.wasm` | 37.7 MB | **yes** |
| `index.js` | 273 KB | no |
| icons/HTML | < 1.5 MB each | no |

There is no Godot exporter option to split the pack, so **Pages cannot serve
this build**. The package therefore ships two complete paths:

| path | commands | status for 0.8.7 |
| --- | --- | --- |
| **R2 + Worker (primary)** | `scripts/upload_r2.ps1` | deployable; hand-coded Brotli/gzip negotiation, versioned immutability |
| Cloudflare Pages (secondary) | `scripts/upload_pages.ps1` | complete config (`wrangler.pages.jsonc`, `_headers`, `_redirects`) but `upload_pages.ps1` **refuses** the current release before calling wrangler, because of the 25 MiB limit |

The Pages files are still generated and validated (`_headers`/`_redirects`) so a
future build that fits the limit, or a Pages-hosted launcher/wrapper page, can
use them unchanged. The marketing site in `website/` is small and can be a
normal Pages project — it is a separate deploy (see `website/README.md`).

## Version-parity flow (three layers, all local)

The release version lives in `godot_project/version.txt` (and
`project.godot`). `pi_setup/sync_web_release.ps1` is the single tool that
writes/checks the Web stamp `version.json` (schema `cartslop.web_release/1`:
game/engine version, build id = sha256 of the payload, per-file bytes + sha256)
and injects `cartslop-*` meta tags into `index.html`.

```
build_0_8_7.ps1 export
   └─ sync_web_release.ps1 -WebDir <builds/v0.8.7/web> -Version 0.8.7        [writes stamp]
        (build fails if version.txt/project.godot disagree)

Deploy-Server.cmd -> sync_web_release.ps1 -Check                             [layer 1]
                  -> deploy_server.ps1 -> sync_web_release.ps1 -Check        [layer 2, before SSH]
web_deploy/scripts/stage_release.ps1 -> sync_web_release.ps1 -Check + re-read
   stamp + build-id layout + self-check                                      [layer 3]
```

`-Check` fails loudly (`WEB RELEASE CHECK FAILED: ...`, exit 1) when the folder
has no stamp, a stale game version, a modified/missing/re-exported file, or an
unknown schema. `stage_release.ps1` refuses a stale folder **before creating
`dist/`**, and `deploy_server.ps1` now runs the check before it opens an SSH
connection, so a stale web folder cannot reach the Pi or the CDN.

Evidence is reproducible with:

```powershell
powershell -ExecutionPolicy Bypass -File web_deploy\scripts\test_version_parity.ps1
# 11 checks: passes for the current export; refuses unstamped / stale-version /
# modified payload / re-exported / missing-file / wrong-schema folders; deploy
# script and deploy .cmd refuse a stale folder; stager refuses and stages the
# good one. Writes builds/_ws1_web/parity-demo.log. Exit code = failures.
```

## Architecture: release layout and caching

Godot's exporter writes fixed file names (`index.html`, `index.js`,
`index.wasm`, `index.pck`), so a flat deployment cannot use
`Cache-Control: immutable` for a 120 MB pack without serving stale bytes on the
next release. The stager puts each release under a content-addressed path:

```
dist/version.json                                   pointer (no-store)
dist/release.json                                   hosting metadata (no-store)
dist/game/<game version>/<build-id[0:12]>/index.html    no-store
dist/game/<game version>/<build-id[0:12]>/index.js      immutable, 1 year
dist/game/<game version>/<build-id[0:12]>/index.wasm    immutable, 1 year
dist/game/<game version>/<build-id[0:12]>/index.pck     immutable, 1 year
dist/game/<game version>/<build-id[0:12]>/version.json  no-store (build pin)
```

`<build-id>` is the sha256 of every payload file computed by the stamp, so any
rebuild changes the URL. The root (`/`, `/index.html`, `/latest`) is a **302**
to the current entry; the target changes per release and must never be cached.
Legacy flat URLs (`/index.pck`, …) get **301**s to the versioned path.

Headers/behaviours are equivalent on both paths:

| response | R2 + Worker (`worker/index.js`) | Cloudflare Pages (`_headers`) |
| --- | --- | --- |
| `/`, `/index.html`, `/latest` | 302 → `release.json.entry` | `_redirects` 302 |
| `/version.json`, `/release.json` | `Cache-Control: no-store, must-revalidate` | same |
| `/game/*/index.html` | no-store | no-store (rule with `! Cache-Control` detach) |
| `/game/*` payloads | `public, max-age=31536000, immutable` | same |
| `Accept-Encoding` | picks `.br` then `.gz` sibling, sets `Content-Encoding`, `Vary: Accept-Encoding` | Cloudflare auto-compresses the origin asset (no siblings needed) |
| security | `nosniff`, `SAMEORIGIN`, strict-origin referrer, permissions policy | same in `_headers` |
| COOP/COEP | only when `THREADED=1` | only when the stager emits them active |

### COOP/COEP: conditional, currently off

The 0.8.7 export sets `variant/thread_support=false` in
`godot_project/export_presets.cfg`, so it is a single-threaded WebAssembly build
and does **not** need `SharedArrayBuffer`; requiring cross-origin isolation
would only add restrictions. The stager reads
`version.json.variant.thread_support` and:
* `false` (current): the Worker sends no COOP/COEP and `_headers` carries them
  commented out with the rationale;
* `true` (future threaded build): COOP `same-origin`, COEP `require-corp`,
  CORP `same-origin` are emitted active automatically (Worker `THREADED` var
  must be set to `"1"` for the R2 path).

## Compression

* **R2 path** — `stage_release.ps1 -Precompress` writes `.gz` (level 9) and
  `.br` (quality 9) siblings once per release; the Worker serves them by
  `Accept-Encoding`. R2 stores them as separate objects (uploaded with
  `--content-encoding`). Measured on the 0.8.7 export: wasm 37.68 MB → 9.61 MB
  gzip / 7.67 MB Brotli, pck 120.92 MB → 101.41 MB gzip / 98.77 MB Brotli
  (the pack is already mostly compressed textures/audio).
* **Pages path** — no siblings needed: Cloudflare compresses text/wasm on the
  fly. `precompress_web.py` is still useful to measure ratios locally.
* Brotli encoding needs either the Python `brotli` module or Node ≥ 18; the
  package bundles `scripts/brotli_compress.mjs` so a plain Windows dev PC with
  Node works. Without either it warns and writes gzip only.

## Manual approval steps (owner actions — credentials never committed)

Nothing below is executed by this package's validation; all of it needs the
owner's Cloudflare account, DNS zone and explicit approval.

1. **Cloudflare account + zone.** Sign in; the final hostname's zone (e.g.
   `cartslop.example`) must be on this account if you want a custom domain
   (otherwise you get `*.pages.dev` / `*.workers.dev` URLs).
2. **API token.** Create a scoped token, never a Global API Key:
   * R2 path: **Workers Scripts: Edit** + **Workers R2 Storage: Edit**
     (Account scope).
   * Pages path (only for a ≤ 25 MiB-per-asset build): **Cloudflare Pages:
     Edit** (Account scope).
   Export it per shell only:
   ```powershell
   $env:CLOUDFLARE_API_TOKEN  = "<token>"
   $env:CLOUDFLARE_ACCOUNT_ID = "<account id>"
   ```
   Both variables are read by the upload scripts; they are never echoed,
   written or committed.
3. **Install the CLI** once (Node.js ≥ 20):
   ```powershell
   cd web_deploy
   npm install
   ```
   The scripts fall back to `npx --yes wrangler@4` if `node_modules` is absent.
4. **R2 bucket** (primary path) — create once:
   ```powershell
   npx wrangler r2 bucket create cartslop-web
   # or:
   powershell -ExecutionPolicy Bypass -File scripts\upload_r2.ps1 -CreateBucket
   ```
   Bucket name is `cartslop-web` (bound as `WEB_ASSETS` in
   `wrangler.r2.jsonc`).
5. **Deploy** the release (stages, guards, precompresses, uploads, deploys the
   Worker, verifies):
   ```powershell
   powershell -ExecutionPolicy Bypass -File scripts\upload_r2.ps1 `
       -BaseUrl https://cartslop-play-r2.<your-subdomain>.workers.dev
   ```
   Exact commands for the Pages alternative (refused for the current 120 MB
   pack, works for ≤ 25 MiB assets):
   ```powershell
   npx wrangler pages project create cartslop-play --production-branch main
   powershell -ExecutionPolicy Bypass -File scripts\upload_pages.ps1 `
       -ProjectName cartslop-play -Branch main `
       -BaseUrl https://cartslop-play.pages.dev
   ```
6. **Custom domain + DNS.** Workers: dashboard → Workers & Pages →
   `cartslop-play-r2` → Settings → Domains & Routes → Add custom domain (or
   uncomment `routes` in `wrangler.r2.jsonc` and re-run `wrangler deploy`);
   Cloudflare creates the `CNAME`/A records. Pages: project → Custom domains.
   **DNS and the certificate are manual owner actions.**
7. **Point the Pi at the CDN.** On the Pi, set
   `Environment=CARTSLOP_WEB_BASE=https://play.<domain>/` in
   `/etc/systemd/system/cartslop-server.service`, then restart
   `cartslop-server` (owner action — out of scope for this release lock).
   `/api/web/version` then reports `web_base` and `/play` labels the primary
   action `PLAY (CLOUD)` with the Pi `/game/` copy as fallback.
8. **Verify** the live URL (read-only, safe to run any time):
   ```powershell
   powershell -ExecutionPolicy Bypass -File scripts\verify_deploy.ps1 `
       -BaseUrl https://play.<domain> -LocalDist dist
   ```
   Then open it in a real browser (WebGL2) — the one check this package cannot
   automate.

## Local validation (no account, no network)

```powershell
cd web_deploy
npm install                                   # once, for wrangler (not needed for validation)
python scripts\validate_package.py            # configs, headers, redirects, Worker, secrets, README
python scripts\audit_logo_parity.py           # official logo on every surface (80 checks)
python scripts\measure_web_release.py `
    --export-dir ..\builds\_ws1_web\export\web `
    --compression-report ..\builds\_ws1_web\precompress-report.json `
    --baseline-dir ..\builds\v0.8.6\web `
    --markdown ..\builds\_ws1_web\measure-web.md
powershell -ExecutionPolicy Bypass -File scripts\test_version_parity.ps1
powershell -ExecutionPolicy Bypass -File scripts\stage_release.ps1 -Force
node --check worker/index.js
```

`python scripts/validate_package.py` also proves the generated `_headers`
avoids the documented Cache-Control join pitfall (two matching rules would be
joined with a comma; the narrower rules detach with `! Cache-Control` first).

## Rollback

* **Pages:** dashboard → project → Deployments → previous production
  deployment → *Rollback* (kept 30 days / last 100).
* **R2 + Worker:** re-upload the previous release's objects (the versioned path
  means old objects are untouched; only `version.json` / `release.json` /
  `_redirects`-equivalent pointer changes), or redeploy the previous Worker
  from git (`wrangler rollback` keeps the previous Worker version). The old
  `/game/<version>/<build>/` payloads stay valid, so a browser that cached them
  keeps working.
* **Pi fallback:** unset `CARTSLOP_WEB_BASE` and restart `cartslop-server`; the
  launcher goes back to `/game/` on the Pi.
* The version stamp is never deleted: every staged release keeps its own
  `version.json`, so a rollback target can be re-verified with
  `sync_web_release.ps1 -Check`.

## Troubleshooting

| symptom | cause / fix |
| --- | --- |
| `WEB STAGE FAILED: ... did not pass the version check` | the export is stale/unstamped/mixed. Re-export with `pi_setup\build_0_8_7.ps1` (it stamps), never hand-edit files after staging. |
| `cloudflare Pages ... 25 MiB` refusal | expected for 0.8.7 — use `upload_r2.ps1`. Re-check in 2027: pages limits may change. |
| root URL 404 | `release.json`/`version.json` were not uploaded, or the Worker was not deployed. Upload the pointer objects and re-run `wrangler deploy`. |
| `Content-Encoding` missing / huge download | Worker path: the `.br`/`.gz` objects were not uploaded (`-Precompress` produces them; `upload_r2.ps1` stages with it by default) or `THREADED`/route mismatch. `verify_deploy.ps1` reports this. |
| wrong MIME for wasm (`application/octet-stream`) | R2 objects were uploaded without `--content-type`; use `upload_r2.ps1`, which sets it per extension. The Worker also falls back to extension mapping. |
| browser shows an old version after deploy | cached root/entry HTML: both are `no-store`; hard-refresh once. Payloads are immutable by build id, so a new build gets new URLs. |
| `/play` still serves the Pi copy | `CARTSLOP_WEB_BASE` not set/restarted on the Pi, or `/api/web/version` unreachable — launcher falls back by design. |

## What is verified locally vs what needs a human

Verified on the dev PC (evidence in `_audit/reports/ws1-web.md`):

* version parity: stamped export passes, seven stale/mixed classes fail, and
  both the Pi deploy path and the CDN stager refuse a stale folder (11/11);
* package configs parse, Worker passes `node --check`, `_headers`/`_redirects`
  rules are valid and avoid the Cache-Control join pitfall, no credentials;
* staging produces the versioned layout, root pointer, immutable/no-store
  header rules, and the real 0.8.7 release's `pages_compatible=false` verdict;
* R2 path precompression produces real `.gz`/`.br` sizes (measured);
* the Pi `webhost.py` serves the staged export locally with correct
  `Content-Encoding`, `no-store` pointers and `/api/web/version`;
* logo audit: 80/80 checks across website, `/play`, console/login, export.

Still manual (owner):

* Cloudflare account, API token scope, bucket/project creation, deploy and
  verification against the live URL;
* custom domain + DNS + certificate;
* `CARTSLOP_WEB_BASE` change and service restart on the Pi;
* a real browser run on WebGL2 hardware (and low-end hardware for the low tier);
* first-load real-world timing from a non-local network.

## Optional: R2 public bucket instead of the Worker

If a Worker is not wanted, the same `dist/` can be published with
`rclone`/`aws s3` to an R2 public bucket behind a custom domain (Cloudflare
documents this). It works, but you lose the explicit `Content-Encoding`
negotiation (first load is 160 MB identity unless the edge compresses the
response) and the Worker's no-store/immutable split must be replaced by
bucket metadata and cache rules. Use the Worker package unless there is a
reason not to.
